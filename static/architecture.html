1. The Ingestion Pipeline (Offline Data Structuring)

Before the application even starts, the system processes raw HR policy PDFs and builds a secure mathematical representation of your company's knowledge. This happens in ingest.py and the `ingestion/` module.

  • PDF Extraction & Cleaning: Standard text extraction strips out noise, headers, and footers to isolate raw policy definitions.
  • Semantic Chunking: The text isn't randomly split by character count. It is intelligently split by headers and numbered policy sections to preserve the context of entire ideas.
  • RBAC Metadata Tagging: This is the core of our data security. During chunking, the code reads the section title. If a section contains words like "Executive" or "Compensation", it assigns a hardcoded array of `allowed_roles: ["manager", "executive"]`. If the text is a general policy, it gets tagged for all roles (including Guests).
  • Vectorization: The text chunks and their security metadata are embedded using a HuggingFace SentenceTransformer and saved locally into the Qdrant database array.

3. The Orchestration Layer: LangGraph Nodes

We use LangGraph as our control plane because it treats Agent behavior like a mathematically dependable state-machine. Here is precisely how traffic flows through the graph structure.

A. The Semantic Router (LLM Touchpoint #1)

Unlike basic chatbots that dump everything into a vector search, our graph's entry point is a zero-shot classification LLM. We send the user's raw query to Gemini with severe system prompts. Gemini is instructed to output exactly one word: RAG, API, or ESCALATE based on the linguistic intent of the query.

B. RAG & The Validation Loop (LLM Touchpoint #2)

If the query is standard policy, it enters the traditional RAG cycle. First, Qdrant utilizes the user's role (extracted securely from the JWT payload) to enforce a rigid filter query. The retrieved documents are then passed to the Validation Node.

Why do we have a Validation Node? Retreival is inherently noisy. LLM Touchpoint #2 takes the User Question and the Qdrant Context and asks Gemini: "Is this context sufficient to answer the question?" If Gemini says "NO", LangGraph utilizes a conditional edge to throw away the noise, increment a retry counter, and force Qdrant to perform a deeper, more expansive search (increasing `k=3` up to `k=6`). This absolutely minimizes AI hallucinations!

C. RAG Generation (LLM Touchpoint #3)

Only once the Validation Node approves the context does it reach the final LLM Node. Here, we feed the Chat History, the validated Qdrant Context, and the user's query into Gemini. The LLM is locked down with strict instructions: "Answer precisely. If the context is empty, state you lack access."

D. Agentic React Tooling (LLM Touchpoint #4)

If the Semantic Router detects a personal question (e.g., "What equipment do I have assigned?"), the entire Qdrant cycle is bypassed. The traffic routes instantly to the API Node. This node instantiates a LangGraph prebuilt React Agent.

Because it is a React (Reasoning + Acting) Agent, we bind Python functions directly to Gemini's brain. Gemini looks at its toolbelt, selects the get_assigned_equipment tool, passes in the user's exact authenticated username, extracts the JSON payload from the mock HR Database, and synthesizes a perfectly contextual final answer.

4. Human-in-the-Loop Safety Engineering (The Hard Cutoff)

If the Semantic Router detects words like "Harassment, Lawyer, Quit, Sue" or an intent to "Speak to a human", the graph forks immediately into the Escalation Node.

This node intentionally avoids invoking an LLM for its response! Generative language models should not be legally trusted with severe employee disputes. Instead, this node executes a pure Python script to log a Support Ticket into data/tickets.py and returns an immutable, company-approved text string (alongside the ticket reference). It also flips an is_escalation = true flag in the FastAPI HTTP payload to trigger dynamic red-alert CSS styling on the frontend.
